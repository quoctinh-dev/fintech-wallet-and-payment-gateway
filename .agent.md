# SECURITY, RBAC & BUSINESS CONSTRAINTS
- **Zero Trust Security**:
  - Xác thực Token JWT tập trung tại API Gateway.
  - Gateway kiểm tra **Redis Blacklist (`jwt:blacklist:<token>`)** khi user Đăng xuất, chặn đứng việc tái sử dụng Token.
  - Sau khi xác thực, Gateway đẩy `X-User-Id` và `X-User-Roles` xuống các service con qua Header.
- **HMAC-SHA256 Payload Signature**:
  - Các API nhạy cảm (`/api/v1/transfers`, `/api/v1/withdrawals`) bắt buộc có `X-Signature`.
  - Gateway cache Request Body an toàn bằng `DataBufferUtils.join()` và `ServerHttpRequestDecorator` (Flux defer) để downstream nhận trọn vẹn Body.
- **Phân quyền RBAC (3 Roles)**: `ROLE_USER`, `ROLE_ADMIN`, `ROLE_AUDITOR`.
- **Phân quyền ngữ cảnh ABAC (Chính chủ)**: User chỉ được xem thông tin ví, số dư và lịch sử của chính mình (`#p0.toString() == authentication.name`).
- **Chống lộng quyền Admin (Anti-Privilege Escalation)**: Admin KHÔNG ĐƯỢC tự khóa mình; Admin KHÔNG ĐƯỢC khóa hoặc hạ quyền Admin khác.
- **Spring Security SpEL Parameter Binding**: Khi dùng SpEL trong `@PreAuthorize`, BẮT BUỘC dùng index tham số (ví dụ `#p0`, `#p1`) thay vì gọi tên biến (như `#userId`) để tránh lỗi `SpelEvaluationException` trên Java 21 / Spring Boot 3.3+.
- **Financial Integrity (Kế toán Kép Bất biến)**: Mọi biến động tài sản bắt buộc ghi vào Sổ cái `ledger_entries` (Debit và Credit đối xứng, tổng `totalDelta == 0.00`). Tuyệt đối KHÔNG có API UPDATE hoặc DELETE trên Sổ cái.

# TESTING & VERIFICATION
- Mọi chức năng sau khi hoàn thành bắt buộc cung cấp kịch bản kiểm thử rõ ràng bằng file `.http` (IntelliJ HTTP Client) hoặc Thunder Client.
- Kịch bản kiểm thử phải bao phủ đủ 4 nhóm:
  1. **Happy Path:** Thành công (200 / 201).
  2. **Validation Error:** Thiếu trường, số tiền âm, sai định dạng (400 Bad Request).
  3. **Security Error:** Chưa đăng nhập (401 Unauthorized), Sai role / Vi phạm chính chủ / Sai HMAC (403 Forbidden).
  4. **Business Error:** Không đủ số dư, trùng Idempotency, tài khoản bị đóng băng (400 / 409 Conflict).
